MP1 (4 sentences)
In UIKit, a manual segue lets an IBAction decide when navigation happens by
calling performSegue(withIdentifier:sender:). Before the next screen appears,
prepare(for:sender:) passes the name, reminder preference and role into
properties on ConfirmationViewController. In Android, an explicit Intent
starts the destination Activity, and putExtra()/getStringExtra() transfer
values through keyed extras rather than directly assigning controller
properties. Both approaches require safe handling of missing input, while
UINavigationController and the Android back stack let the user return to
the previous screen.

MP2 (4 sentences)
UITableView asks its data source for a row count and reusable cells, much as
RecyclerView uses an adapter and view holders to display a changing list.
ClubCell.configure(with:) fills the reused row with a club's image, name and
category, while row selection sends the selected club to the detail screen.
Core Data manages model objects, a context and a persistent store, which
serve a similar persistence purpose to Room or SQLiteOpenHelper even though
their APIs and object-management approaches differ. UserDefaults, like
SharedPreferences, suits small settings such as the student's name, reminder
choice and role, while the collection of clubs belongs in structured storage.
