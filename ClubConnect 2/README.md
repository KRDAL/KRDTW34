# ClubConnect

A single UIKit/Storyboard application implementing the MP1 welcome and registration flow and extending it with MP2's directory and local persistence. It is a newly authored project; it does not reuse Campus Companion files.

## Run

Extract the ZIP, open `ClubConnect.xcodeproj`, choose the **ClubConnect** scheme and an installed **iPhone Simulator**, then press **Command-R**. The deployment target is iOS 15.0; use Xcode 14 or newer. No external packages are required. For a real device, set your own signing team and bundle identifier.

The app starts at a navigation controller containing Welcome. **Join the Club** pushes Confirmation. **Browse Clubs** pushes the club directory; selecting a row pushes the same Confirmation controller with an optional selected club. UIKit provides the Back buttons.

## File guide

| File | Purpose |
| --- | --- |
| `WelcomeViewController.swift` | Form outlets, title assignment, keyboard handling, manual segues, safe data passing and UserDefaults |
| `ConfirmationViewController.swift` | Registration summary and optional club details |
| `ClubListViewController.swift` | Table data source/delegate, fetch/seed/add/save and row navigation |
| `ClubCell.swift` | Custom prototype cell outlets and `configure(with:)` |
| `AppDelegate.swift` | App lifecycle and the persistent Core Data container |
| `SceneDelegate.swift` | Storyboard-based scene/window lifecycle |
| `Base.lproj/Main.storyboard` | Four scenes, manual segues, outlets, actions and Auto Layout |
| `ClubConnect.xcdatamodeld` | Club entity: `name`, `category`, `iconName`; Class Definition code generation |

The final `Club` class is generated by Xcode from the data model. There is deliberately no handwritten `Club.swift` in the final target, which avoids duplicate class declarations. The earlier MP2 Part A milestone uses a struct, which is replaced in Part D. Apple documents the code generation settings at https://developer.apple.com/documentation/coredata/generating-code .

The scene manifest names `Main` as its storyboard and `SceneDelegate` as its delegate. See https://developer.apple.com/documentation/uikit/uisceneconfiguration/storyboard .

## Persistence behavior

Both Welcome actions save the current form values before navigation. The form restores a saved name with `string(forKey:)`, reminders with `bool(forKey:)`, and the role index with `integer(forKey:)`. Named private enum keys prevent repeated key literals. Registered defaults handle first launch, and an invalid stored role index falls back to Member.

The directory fetches `Club` records from the persistent container's view context. If the fetched collection is empty, it inserts five starter clubs and saves once. Add Club trims both fields, rejects blank values, inserts a new record, saves, fetches again and reloads. Names sort alphabetically. Storage errors produce alerts rather than a forced crash. The reminder switch only stores a preference; actual notification scheduling is outside these modules.

Persistence is local to the installed app. Do not delete the app, erase the Simulator or change the bundle ID while testing relaunch behavior. Different Simulator devices have separate app data.
